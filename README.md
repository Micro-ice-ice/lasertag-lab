# Lasertag Lab

Статический сайт для разбора игр IFLED: каталог, матрица попаданий, рейтинги, личные профили и противостояния. Постоянно работающий сервер и база данных не нужны.

## Как устроено

1. GitHub Actions запрашивает `https://data.ifled.info/games/index.json` каждые 30 минут (на 17-й и 47-й минутах часа).
2. Скрипт копирует JSON только новых и изменённых открытых игр. Скрытые игры и их старые копии удаляются из публикуемого набора.
3. После успешной синхронизации собирается и публикуется обычный статический сайт на GitHub Pages.
4. Браузер читает `data/catalog.json`, а полный JSON игры скачивает только после выбора. Запросов браузера к IFLED и собственного API нет.

Каталог показывает дату, площадку и число игроков; доступны поиск по дате/площадке/ID, сортировки и прямые ссылки. Последние восемь открытых игр сохраняются в браузере. Адрес игры — `?game=GAME_ID`, личного профиля — `?game=GAME_ID#player=…`.

Каждый JSON игры имеет SHA-256 в имени файла: обновлённая статистика получает новый URL. Браузерный кэш сверяется с версией в каталоге. Кнопка «Обновить список» перечитывает опубликованный каталог; она не запускает GitHub Actions и не запрашивает IFLED. При отсутствии связи используется сохранённый каталог и ранее открытые игры. Это не PWA: для первого открытия самой страницы нужен доступ к сайту.

В интерфейсе указано время последней успешной синхронизации с IFLED. Новая игра появится после очередной успешной синхронизации и публикации. Расписание GitHub Actions может задерживаться; в публичном репозитории GitHub отключает его после 60 дней отсутствия активности. В этом случае включите workflow в Actions. [Ограничения расписания GitHub](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#schedule).

## Локальный запуск

Нужен Node.js 22.12+ (рекомендуется 24) только для разработки, синхронизации и сборки.

```sh
npm ci
npm run sync:games
npm run dev
```

Синхронизированные данные уже находятся в `static/data/catalog.json` и `static/data/games/`. Повторная синхронизация проверит каталог и повторно использует неизменившиеся файлы. Встроенная игра 9 октября 2026 (`aZ0dpB6H`) служит примером при первом открытии, пока игрок не выбрал другую.

## Проверка и сборка

```sh
npm run check
npm test
npm run build
npm start
```

`npm start` — только локальный просмотр статической сборки на `http://127.0.0.1:3000`, без API и запросов к IFLED. Готовый каталог `build/` можно разместить на любом статическом хостинге. После `npm run sync:games` повторите сборку, чтобы новые данные попали в `build/`.

Для вложенного пути в PowerShell:

```powershell
$env:BASE_PATH = '/lasertag-lab'
npm run build
npm run preview
Remove-Item Env:BASE_PATH
```

## Публикация на GitHub Pages

Репозиторий: [Micro-ice-ice/lasertag-lab](https://github.com/Micro-ice-ice/lasertag-lab). Публикация запускается при отправке изменений в `main`, вручную или по расписанию.

Адрес сайта: [micro-ice-ice.github.io/lasertag-lab](https://micro-ice-ice.github.io/lasertag-lab/). Состояние публикации доступно во вкладке [Actions](https://github.com/Micro-ice-ice/lasertag-lab/actions/workflows/pages.yml).

1. Загрузите проект в репозиторий GitHub, включая `static/data/`, `package-lock.json` и `.github/workflows/pages.yml`.
2. В Settings → Pages выберите Source: GitHub Actions.
3. Убедитесь, что workflow находится в основной ветке, и запустите **Publish to GitHub Pages** через Run workflow.
4. После этого расписание будет проверять новые игры каждые 30 минут. Тот же Run workflow позволяет синхронизировать и опубликовать сайт вручную.

Workflow автоматически задаёт путь по имени репозитория, а для `username.github.io` использует корень. Для собственного домена задайте пустой `BASE_PATH` в шаге сборки. Кэш Actions сохраняет скачанные игры между запусками; отсутствие кэша безопасно — скрипт скачает их заново. Если источник недоступен или данные некорректны, workflow завершится ошибкой до публикации, а уже опубликованная версия останется доступной. Никаких автоматических коммитов в репозиторий не производится.

## Статистика и профили

- Карта «кто → в кого», выбор пары, переключение между попаданиями и балансом, сортировка игроков.
- Личный профиль: попадания, баланс, точность, рейтинг IFLED, выстрелы, ранения, места среди участников и сравнение со средним.
- Личные пары с поиском и фильтрами преимущества, отставания и равного счёта. Сортировка — нажатием на заголовок столбца; повторное нажатие меняет ↑/↓.
- Рейтинг Lab v1 от 0 до 100 без точности, количества выстрелов и рейтинга IFLED. Он доступен в профиле и сортировках игроков.
- «Это я» запоминает позывной только в текущем браузере; если он есть в другой игре, профиль доступен и там.
- Скачивание JSON выбранной игры и проверка согласованности итогов.

`hitsOut` — попадания в указанного участника, `hitsIn` — полученные от него. Отсутствующая пара остаётся неизвестной. Баланс равен попаданиям минус ранения от известных игроков. Разница `AllWounds` и `Wounds` не распределяется по стрелявшим искусственно. Цвет команды не означает постоянный состав за всю игру. Время событий и раунды эта визуализация не использует.

Места при равных значениях одинаковые; для ранений меньшее значение получает более высокое место. Точность и рейтинг IFLED берутся из исходной выгрузки; средняя точность — среднее по игрокам. Преимущество по попаданиям не означает победу в раунде.

### Рейтинг Lab v1

Это экспериментальная оценка результата внутри конкретной игры. H и W — суммы нанесённых и полученных попаданий из записей пар. Формула с округлением до одного знака: `100 × (0,60 × E + 0,25 × V + 0,15 × D)`.

- `E = (H + 25) / (H + W + 50)` — эффективность обменов, вес 60%.
- `V = H / (H + среднее H по всем участникам)` — объём результативного вклада, вес 25%.
- `D = (пары с преимуществом + 0,5 × равные пары + 2) / (активные пары + 4)` — преимущество в противостояниях, вес 15%.

Активная пара содержит хотя бы одно попадание в любую сторону. Неизвестные пары, пары 0:0 и нераспределённые ранения не входят в расчёт. Поправки +25 и +2 сглаживают малую статистику; без записанных попаданий рейтинг и место отсутствуют. Нейтральный ориентир 50 соответствует равным обменам, среднему H и половине пар с преимуществом. Точность, Fire, Killed и рейтинг IFLED на Lab не влияют. Время участия, задачи и сила соперников неизвестны, поэтому оценку нельзя считать общей мерой мастерства или напрямую сравнивать между играми. Подробности и компоненты доступны под карточками профиля.

## Структура

- `scripts/sync-games.mjs` — проверка публичного каталога, копирование игр и атомарное обновление локального каталога.
- `.github/workflows/pages.yml` — синхронизация, кэш скачанных файлов, проверки, сборка и публикация по расписанию или вручную.
- `static/data/catalog.json`, `static/data/games/` — готовый статический набор данных.
- `src/lib/game-source.js` — проверка данных, чтение каталога и браузерный кэш.
- `src/lib/analytics.js` — расчёты статистики.
- `src/lib/components/GameLoader.svelte` — каталог и открытие игры.
- `src/lib/components/PlayerExplorer.svelte` — личные профили.
- `src/lib/components/HitMatrix.svelte` — матрица попаданий.
- `src/routes/+page.svelte`, `src/routes/style.css` — страница и оформление.
- `test/` — расчёты, статическая загрузка, кэш и синхронизация без сетевых запросов.

CLI `npm run import:game -- GAME_ID` остаётся для ручного сохранения исходного снимка в проекте. Для обновления каталога сайта используйте `npm run sync:games`.
